# Shared scaffold — author chapters, let the core build

Every torsor document is built by the **unified core** at
`${CLAUDE_PLUGIN_ROOT}/tools/core/`. The skill's job is to author content and a small
manifest; the core owns the preamble, Makefile, vendored tooling, and every output
format. Do **not** hand-build `main.tex`, the Makefile, the colophon, or copy tools in —
the core generates all of that. (This replaces the old inlined Makefile/preamble, which
now lives once, in the core.)

## What the skill produces

Work inside the document directory `<doc-dir>/`:

```
<doc-dir>/
  latex/
    chapters/     <- YOU author these: 00-preface.tex, 01-*.tex, ...
    assets/       <- images/cover the chapters use (optional)
  build.yaml      <- YOU write this manifest
```

Everything else — `main.tex`, `Makefile`, `STYLE.md`, `tex2torsor/`, `check-build.py`,
`formats/`, `features/`, `config.mk`, `.gitignore`, and the built `latex/<stem>.pdf`,
`html/`, `epub/`, `markdown/` — is generated by the core.

## The manifest (build.yaml)

```yaml
genre:  manual | technical-doc | paper-guide | topic-guide | study-guide | body-of-work | state-guide
stem:   <output-stem>            # optional; defaults to the doc-dir name
title:    "<Title>"
subtitle: "<Subtitle>"           # optional
tagline:  "<one-line tagline>"   # optional
blurb:    "<lower title-page line>"   # optional
author:   "torsor lab"           # optional
voice:    01-direct              # optional; recorded in STYLE.md
cover:    <path/to/cover.png>    # optional; PDF title page + EPUB cover + HTML image
bibliography: <path/to/refs.bib> # optional; turns on citations (the bib feature)
extra_features: [math]           # optional; APPEND to the genre's defaults
features: [callouts, listings]   # optional; REPLACE the genre's defaults entirely
chapters:                        # optional; controls structure & order
  frontmatter: [00-preface]
  mainmatter:  [01-foo, 02-bar]
  appendix:    [appendix-x]      # optional
  backmatter:  [afterword]       # optional
```

Omit `chapters` to fall back to filename order (00-* → front matter, the rest → main
matter). Each genre supplies default features and a prose base:

| Genre         | Default features   |
|---------------|--------------------|
| manual        | callouts, listings |
| technical-doc | callouts, listings |
| paper-guide   | callouts, math     |
| topic-guide   | callouts, math     |
| study-guide   | callouts, math     |
| body-of-work  | callouts, math     |
| state-guide   | callouts, math     |

A math-bearing manual (code **and** math, e.g. a CLI reference for a mathematical tool):
`genre: manual` + `extra_features: [math]` → `callouts, listings, math`.

## Build

Author the chapters and `build.yaml`, then assemble in place and build:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/tools/core/assemble.py <doc-dir>/build.yaml <doc-dir> --in-place
cd <doc-dir> && make all
```

`assemble.py --in-place` scaffolds `main.tex` + tooling **around** your authored chapters
— re-run it any time after editing chapters or the manifest; it is idempotent. `make all`
builds every registered format (PDF, HTML, both EPUBs when math is on, Markdown) and runs
`check-build.py`.

If the source is **Markdown** rather than authored LaTeX, use the from-markdown front-end
instead (it converts to the chapter tree, then assembles — `fit_tables` defaults on):

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/tools/core/frontend_markdown.py <manifest.yaml> <doc-dir> --force
```

## Authoring notation

- **Callouts** (all genres): `\begin{notebox}...\end{notebox}`, `warnbox`, `pitfallbox`.
- **Code** (needs `listings`, on for manual/technical-doc): fenced `lstlisting`; inline
  `\code{...}` is breakable, so long paths/commands wrap.
- **Math** (needs `math`): `$...$`, `\[...\]`, and the theorem environments
  `paperthm` / `paperdefn` / `paperlem` / `paperprop` / `papercor` — carry the source's own
  number in the optional argument, e.g. `\begin{paperthm}[Theorem 4.2]`.
- **Citations** (needs `bib`, auto-on when the manifest sets `bibliography:`): `\cite{key}`,
  `\textcite{key}`, `\parencite{key}`, and `\printbibliography` where the bibliography
  should appear (typically a backmatter references chapter). The PDF renders via
  biblatex+biber (alphabetic style); HTML/EPUB/Markdown resolve the same cites via pandoc
  `--citeproc` (author-date style) — the two styles differ.
- **Cover**: set `cover:` in the manifest — it appears on the PDF title page, as the EPUB
  cover, and as an image in the HTML (images are responsive by default).
- **Tables**: author normally; `fit_tables` (from-markdown default, opt-in for authored
  LaTeX) rescales wide columns to the page. Very wide tables that still overrun are
  reviewer-tier redesign, not a build fix.

The house design — palette, fonts, headings, box styles, `\code`, colophon — lives once in
the core's `base/` preamble and per-feature slices, and is not re-specified per document.
Do not alter it without the user's agreement; these are family-wide constants.

## Verify — the publication pass

`make all` runs `check-build.py` (tier 1: fresh PDF, no LaTeX errors, no undefined refs,
overfull hboxes over threshold, non-ASCII in listings, all declared outputs present). A
document is not done until the full **publication pass** has run — see
`${CLAUDE_PLUGIN_ROOT}/assets/commons/publication.md`.
